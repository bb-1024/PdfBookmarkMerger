UI Code-Behind Manual Verification Checklist

A checklist for visually verifying, before release, drag & drop, Adorner rendering, dialog display, and other UI behavior that has not been automated as tests.

01Purpose

The code-behind of PdfBookmarkMerger.Wpf / PdfBookmarkMerger.Avalonia (MainWindow.xaml.cs / MainWindow.axaml.cs, etc.) is heavily dependent on actual OS input and window display events, such as drag & drop, Adorner rendering, and dialogs shown through a real window.

Attempting to automatically verify this with unit tests such as xUnit would require introducing, separately, either WinAppDriver or System.Windows.Automation for WPF, and headless rendering via Avalonia.Headless for Avalonia. Once you factor in simulating mouse-drag coordinates and verifying AdornerLayer rendering, the cost of building and maintaining the automated-test infrastructure itself far exceeds that of testing the logic side (the App-layer ViewModels). For that reason, the policy is that, for the time being, the App-layer ViewModels (PdfBookmarkMerger.App.Tests) are covered by automated logic tests, while the UI code-behind is verified manually before each release using this checklist.

Note Operational Update

In practice, using Avalonia.Headless for scratch verification during individual bug investigations — actually laying out a window and asserting control coordinates/state — has proven effective (a missing default-value propagation for TreeViewItem.IsExpanded and a mismatch in hierarchy-indent width were both identified and fixed this way; see Platform-Specific Notes in the design document for details). Incorporating this as a standing automated test would require estimating, item by item, how much of this checklist can be made headless, so for now both approaches are used together: "ad hoc verification during bug investigation" and "visual confirmation via this checklist before release."

If UI automated testing is invested in going forward, it is recommended to first verify, on a small scale, how far a common E2E scenario can be written that works for both WPF and Avalonia, and then gradually migrate the items in this checklist to automation.

02Verification Procedure

Verify each item on both the Windows build (WPF-UI) and the macOS build (Avalonia). If a discrepancy that reproduces on only one platform is found, determine whether it is an intentional implementation difference or a missed fix.

#AreaVerification StepsExpected Result
1File List: Placeholder DisplayOpen the main screen with no files added yetHint text such as "Drag & drop PDF files or a folder here" is displayed overlaid on the list area
2File List: Drag & Drop from ExplorerSelect multiple PDF files in Explorer and drag & drop them onto the windowThe dropped files are added to the list, and the page count for each is displayed asynchronously shortly after
3File List: Drag & Drop of a FolderDrag & drop a folder that contains PDF filesOnly the *.pdf files directly under the folder are added, in ascending order by file name (contents of subfolders are not added)
4File List: Reordering via Internal Drag & DropDrag a row within the list and drop it at the position of another rowThe row moves to the drop position, and this is reflected in the subsequent merge order as well
5File List: Move Up/Down and Delete ButtonsSelect a row and perform each of the Move Up / Move Down / Delete operationsThe selected row moves or is deleted as expected
6Handling of Files That Fail to LoadMix a password-protected PDF or a corrupted PDF into the list and click "Next"An error dialog is displayed for the affected file, and only the successfully loaded files are reflected in the bookmark editing screen. The failed file is also excluded from the subsequent merge, even though it remains in the list (it is excluded via the LoadFailed flag)
7Bookmark Tree: Initial Expansion StateLoad a file containing bookmarks with 3 or more hierarchy levels, and check the display immediately after transitioning to the bookmark editing screenAll nodes are displayed in an expanded state (not collapsed) (the default value true of BookmarkNodeViewModel.IsExpanded is reflected in the TreeViewItem)
8Bookmark Tree: Reordering via Drag & Drop (Sibling)Drag a bookmark row and drop it on the lower half of the target rowThe row is inserted as the next sibling immediately after the target row. A line (indicator) is shown at the insertion position
9Bookmark Tree: Re-parenting via Drag & Drop (Insert as Child)Drag a bookmark row and drop it on the upper half of the target rowThe row becomes the first child of the target row. The destination parent is automatically expanded
10Bookmark Tree: Rejecting Drops onto One's Own DescendantsDrag & drop a parent node onto one of its own child nodesNothing happens (the tree structure is not broken)
11Bookmark Tree: Title Column Width Adjustment and Vertical AlignmentSet titles of different lengths on multiple bookmarks at different hierarchy depths (parent, child, grandchild)The title column widens to fit the longest title, and regardless of hierarchy depth, the horizontal position of the following columns (display method, Left/Top/Zoom, etc.) stays aligned (the title column width correctly shrinks by the amount of indentation for each level)
12Bookmark Tree: Add/Delete OperationsRun through each of the Add Root, Add as Child, Add as Sibling, and Delete buttonsEach operation is reflected at the expected position, and the remaining tree structure is not broken after deletion
13Bookmark Tree: Child Level Limit SettingOn a node with 3 or more levels of descendants, use the "Child Element Level Limit" operation and select an intermediate levelAll nodes deeper than the selected level are deleted. The operation is disabled for nodes that cannot open the dialog (i.e., nodes with no children)
14Bookmark Tree: Uniform Fit SettingToggle "Set All to Fit" ON and OFFWhile ON, the display method and coordinate fields are uneditable for all rows and are treated as Fit. Turning it back OFF restores each row's original settings (including coordinates)
15Bookmark Tree: Uniform Expansion SettingSwitch "Set Expansion for All" between Expand All / Collapse All / IndividualThe expanded/collapsed state of rows with children switches all at once. Switching back to Individual restores the state prior to the switch
16Merge / Save DialogRun "Merge" and try both Cancel and Save in the save destination dialogNothing happens on Cancel. On Save, the file is generated at the specified destination and a completion message is displayed
17Property Editing DialogTurn ON "Show property dialog when merging" in settings, then mergeThe first file's properties are displayed as the initial values, and the edited content is reflected in the merged PDF
18Settings Dialog / Theme SwitchingIn the settings dialog, switch the theme to Light / Dark / Follow System, one at a timeThe color scheme of the entire screen changes immediately upon switching. "Follow System" tracks the OS theme changes
19Log Output on Unhandled Exception (Applicable Builds Only)(If a development build allows intentionally triggering an exception) Trigger an unhandled exception by some meansA Fatal-level log entry is recorded to %AppData%/PdfBookmarkMerger/logs/pdfbookmarkmerger-.log before the app exits
20Loading a File with a Large Number of Bookmarks / Progress DisplayLoad, in a batch, a PDF file with a large number of bookmarks (or a large number of PDF files) and click "Next". Try a scale that takes 5 seconds or moreWhile loading, all controls on the step-1 screen become unresponsive, and a dark overlay with an in-progress message is displayed. After 5 seconds have elapsed, the completed/total count and the name of the file currently being processed are additionally displayed. For small loads that finish in under 5 seconds, the detailed display never flickers into view
21Progress Display During Merge ExecutionWhen merging multiple files, check the overlay and progress display in the same way as in item 20All controls become unresponsive during the merge as well, and progress (completed/total file count and the name of the file currently being processed) is displayed
22File List: Disabling the Move Up/Down Buttons at the BoundariesSelect only the first row and press "Move Up"; select only the last row and press "Move Down". Also check the state where nothing is selectedThe button for the corresponding direction is disabled (pressing it does nothing). When nothing is selected, both Move Up and Move Down are disabled
23File List: Batch Move on Multi-Selection / Non-Contiguous SelectionSelect multiple contiguous rows and press Move Up/Down. Then make a multi-selection with unselected rows interspersed between themWith a contiguous selection, the entire selected block moves together while preserving its relative order. With a non-contiguous selection, both Move Up and Move Down become disabled
24Bookmark Tree: Auto-Scroll During Drag & DropWhile dragging a bookmark, keep the cursor near the top or bottom edge of the tree's visible areaWhile the cursor remains in that position, the tree keeps auto-scrolling, making it possible to drop onto rows outside the visible area
25Bookmark Tree: Selection by Clicking the Margin AreaClick the margin to the left of the level indicator (Lv.N) and the margin to the right of the merged-page displayThe clicked row becomes selected (TreeView.SelectedItem changes). However, the highlight (background color) is still applied only to the range where the element actually exists, as before
26Bookmark Tree: Promote/Demote Level ButtonsSelect a node with children or nodes at various hierarchy levels, and press "Promote Level" / "Demote Level". Also try promoting a node directly under the root, and demoting the first elementThe hierarchy level becomes one step shallower/deeper (sibling relationships are rearranged correctly). "Promote Level" is disabled for nodes directly under the root, and "Demote Level" is disabled for the first element (one with no preceding sibling)
27Bookmark Tree: Level Limit Options Include the Node's Own LevelOn a node with children, open "Set Child Element Level Limit" and choose the minimum option (its own level)The node's own level is included in the list of options. Selecting it and clicking OK deletes all of that node's children
28Bookmark Tree: UndoPerform a combination of title edits, additions, deletions, moves, level changes, and level-limit settings several times, then repeatedly press "Undo"The state reverts step by step from the most recent edit (in LIFO order). Consecutive typing into the same input field is undone together as a single edit. Once nothing more can be undone, the "Undo" button becomes disabled. Toggling "Set All to Fit" or "Set Expansion for All" ON/OFF is itself not covered by "Undo" (turning the checkbox back OFF directly restores the original value)
29Bookmark Tree: Button Layout / Initial Window SizeOpen the bookmark editing screen and check the order of the first row (level operations, 3 add types, delete, level limit) and second row (settings, back, undo, 2 uniform-setting toggles, save), as well as whether the buttons fit within the window in its initial stateThe order matches the specified layout. At the initial window size (1300×760), the buttons on every row fit within the screen without overflowing
30Canceling Dialogs with EscOpen each of the "Set Child Element Level Limit", "PDF Properties", and "App Settings" dialogs, and press the Esc key while some element has focusEvery dialog closes as if canceled (changes are discarded)
31Automatic Display Language Detection / SwitchingStart the app for the first time (with no settings file present) and check the UI language. Then switch the language in the settings dialog, save, and restart the appOn first launch, the UI is displayed in Japanese if the OS display language is Japanese, and in English otherwise. The language switched and saved in the settings dialog is reflected across the entire UI (window title, buttons, messages, dialogs) starting from the next launch (the currently running screen does not switch in place)
32Settings File Save LocationAfter changing and saving some setting in the app, check the folder containing the executable. Also check %AppData%/PdfBookmarkMerger/settings.json is created/updated in the same folder as the executable. No settings file is created under %AppData%/PdfBookmarkMerger/; only the logs/ folder exists there
