UIコードビハインド 手動確認手順書

自動テスト化していないD&D・Adorner描画・ダイアログ表示等を、リリース前に目視確認するための手順書。

01位置づけ

PdfBookmarkMerger.Wpf / PdfBookmarkMerger.Avalonia の コードビハインド(MainWindow.xaml.cs / MainWindow.axaml.cs 等)は、 ドラッグ&ドロップ・Adorner描画・実ウィンドウを介したダイアログ表示など、実際のOS入力やウィンドウ表示イベントに 強く依存する。

これらをxUnit等の単体テストで自動検証しようとすると、WPFは WinAppDriverや System.Windows.Automation、AvaloniaはAvalonia.Headlessによる ヘッドレスレンダリングをそれぞれ個別に導入する必要があり、マウスドラッグの座標シミュレーションや AdornerLayerの描画確認まで含めると自動テスト基盤自体の構築・保守コストがロジック側(App層ViewModel)の テストを大きく上回る。そのため、当面はApp層のViewModel(PdfBookmarkMerger.App.Tests)で ロジックを自動テストし、UIコードビハインドはリリース前にこの手順書で手動確認する方針とする。

補足 運用アップデート

個別の不具合調査ではAvalonia.Headlessを使い、実際にウィンドウをレイアウトして コントロールの座標・状態をアサートするスクラッチ検証を行う運用が実際に有効だった (TreeViewItem.IsExpandedの既定値反映漏れ、階層インデント幅の食い違いを この方法で特定・修正済み。詳細は設計ドキュメントのプラットフォーム固有の留意点を参照)。 恒常的な自動テストとして組み込むには、この手順書の各項目をどこまでヘッドレス化できるかを個別に見積もる必要があるため、 現時点では「不具合調査時のスポット検証手段」と「リリース前の本手順書による目視確認」を併用する。

将来的にUI自動テストへ投資する場合は、まずWPF/Avalonia双方で共通して使えるE2Eシナリオがどこまで書けるかを 小さく検証してから、本手順書の項目を段階的に自動化へ移行することを推奨する。

02確認手順

各項目、Windows版(WPF-UI)・macOS版(Avalonia)の両方で確認する。 片方でしか再現しない差異が見つかった場合は、意図した実装差か・修正漏れかを切り分けること。

#機能領域確認手順期待結果
1ファイル一覧: プレースホルダー表示ファイルを1件も追加していない状態でメイン画面を開く「PDFファイルまたはフォルダをここにドラッグ&ドロップ」等のヒントテキストが一覧領域に重なって表示される
2ファイル一覧: エクスプローラーからのD&DエクスプローラーからPDFファイルを複数選択してウィンドウにドラッグ&ドロップするドロップしたファイルが一覧に追加され、直後にページ数が非同期で表示される
3ファイル一覧: フォルダのD&DPDFを含むフォルダをドラッグ&ドロップするフォルダ直下の*.pdfのみがファイル名の昇順で追加される(子フォルダの中身は追加されない)
4ファイル一覧: 内部D&Dによる並べ替え一覧内の行をドラッグして別の行の位置にドロップするドロップ先の位置に移動し、以降の結合順にも反映される
5ファイル一覧: 上下移動・削除ボタン行を選択し、上へ/下へ/削除の各操作を行う選択行が期待通りに移動・削除される
6読み込み失敗ファイルの扱いパスワード保護PDFや破損PDFを一覧に混ぜて「次へ」を実行する該当ファイルについてエラーダイアログが表示され、しおり編集画面には正常ファイルのみが反映される。その後の結合でも失敗ファイルは結合対象に含まれない(LoadFailedフラグにより一覧に残っていても除外される)
7しおりツリー: 初期展開状態3階層以上のしおりを含むファイルを読み込み、しおり編集画面に遷移した直後の表示を確認する全ノードが展開表示された状態(折りたたまれていない)で表示される(BookmarkNodeViewModel.IsExpanded既定値trueがTreeViewItemに反映されていること)
8しおりツリー: D&Dによる並べ替え(兄弟)しおり行をドラッグし、対象行の下半分にドロップする対象行の直後の兄弟として挿入される。挿入位置に線(インジケータ)が表示される
9しおりツリー: D&Dによる再親子付け(子として挿入)しおり行をドラッグし、対象行の上半分にドロップする対象行の先頭の子としてぶら下がる。移動先の親が自動的に展開される
10しおりツリー: 自分の子孫へのドロップ拒否親ノードを自分の子ノードの上にドラッグ&ドロップする何も起こらない(ツリー構造が破綻しない)
11しおりツリー: タイトル列幅の追従・縦位置の整列階層の深さが異なる複数のしおり(親・子・孫)に、長さの異なるタイトルを設定するタイトル列の幅が最長タイトルに合わせて広がり、階層の深さに関わらず表示方法・Left/Top/Zoom等の後続列の横位置が揃ったままになる(階層ごとのインデント分だけタイトル欄の幅が正しく縮む)
12しおりツリー: 追加/削除操作ルート追加・子として追加・兄弟として追加・削除の各ボタンを一通り実行するそれぞれ期待した位置に反映され、削除後も残りのツリー構造が壊れない
13しおりツリー: 子レベル上限設定3階層以上の子を持つノードで「子要素のレベル上限」操作を行い、中間の階層を選択する選択した階層より深いノードがすべて削除される。ダイアログが出せない(子を持たない)ノードでは操作不能になっている
14しおりツリー: 一律Fit設定「一律でFitに設定」をON/OFFするONの間は表示方法・座標欄が全行で編集不可になりFit扱いになる。OFFに戻すと各行の元の設定(座標含む)が復元される
15しおりツリー: 一律展開設定「一律で展開表示を設定」を全展開/全収納/個別設定に切り替える子を持つ行の開閉状態が一括で切り替わる。個別設定に戻すと切り替え前の状態に復元される
16結合・保存ダイアログ「結合」を実行し、保存先ダイアログでキャンセル/保存の両方を試すキャンセル時は何も起こらない。保存時は指定先にファイルが生成され、完了メッセージが表示される
17プロパティ編集ダイアログ設定で「結合時にプロパティダイアログを表示する」をONにして結合する先頭ファイルのプロパティが初期値として表示され、編集内容が結合後PDFに反映される
18設定ダイアログ・テーマ切り替え設定ダイアログでテーマをライト/ダーク/システム設定にそれぞれ切り替える切り替え直後に画面全体の配色が変わる。「システム設定」ではOSのテーマ変更に追従する
19未処理例外時のログ出力(該当版のみ)(開発ビルドで意図的に例外を発生させられる場合)何らかの形で未処理例外を発生させるアプリ終了前に%AppData%/PdfBookmarkMerger/logs/pdfbookmarkmerger-.logにFatalレベルのログが記録される
20大量しおりファイルの読込・進捗表示しおりを大量に含む(または多数の)PDFファイルを一括で読み込み、「次へ」を実行する。5秒以上かかる規模で試す読込中は手順1画面の全コントロールが操作不能になり、暗いオーバーレイと処理中メッセージが表示される。5秒経過後、完了/総数件数と処理中のファイル名が追加表示される。5秒未満で終わる小規模な読込では詳細表示が一切ちらつかない
21結合実行時の進捗表示複数ファイルを結合する際、20と同様にオーバーレイ・進捗表示を確認する結合中も全コントロールが操作不能になり、進捗(完了/総数ファイル数・現在処理中のファイル名)が表示される
22ファイル一覧: 上下ボタンの境界での非活性化先頭行のみ選択して「上へ」、末尾行のみ選択して「下へ」を押す。何も選択しない状態も確認する該当方向のボタンが非活性(押しても何も起きない)になっている。未選択時は上下ボタンとも非活性
23ファイル一覧: 複数選択時の一括移動・非連続選択連続する複数行を選択して上へ/下へを押す。次に、間に非選択行を挟む形で複数選択する連続選択時は選択ブロック全体が相対順序を保ったまままとめて移動する。非連続選択時は上下ボタンとも非活性になる
24しおりツリー: D&D中の自動スクロールしおりをドラッグしたまま、ツリー表示範囲の上端・下端付近にカーソルを置き続けるカーソルがその位置にある間、ツリーが自動的にスクロールし続け、表示範囲外の行にもドロップできるようになる
25しおりツリー: 余白部分クリックでの選択レベル表示(Lv.N)の左側の余白、および結合後ページ表示の右側の余白をクリックするクリックした行が選択状態になる(TreeView.SelectedItemが変わる)。ただし強調表示(背景色)は従来通り要素が存在する範囲のみに適用される
26しおりツリー: レベル上げ/下げボタン子を持つノードや複数階層のノードを選択し、「レベルを上げる」「レベルを下げる」を押す。ルート直下のノードでレベルを上げる、先頭要素でレベルを下げる操作も試す階層が1段浅く/深くなる(兄弟関係が適切に組み替わる)。ルート直下では「レベルを上げる」が、先頭要素(直前の兄弟が無い)では「レベルを下げる」がそれぞれ非活性になっている
27しおりツリー: レベル上限設定の選択肢に自身のレベルを含む子を持つノードで「子要素のレベル上限を設定」を開き、選択肢の最小値(自身のレベル)を選ぶ選択肢の一覧に自身のレベルが含まれている。それを選択してOKすると、そのノードの子要素がすべて削除される
28しおりツリー: 元に戻す(Undo)タイトル編集・追加・削除・移動・レベル変更・レベル上限設定を組み合わせて何回か行った後、「元に戻す」を繰り返し押す直前の編集から順に(LIFO順で)元の状態に戻っていく。同じ入力欄への連続したタイプ入力は1回の編集としてまとめて戻る。これ以上戻せなくなると「元に戻す」ボタンが非活性になる。「一律でFitに設定」「一律で展開表示を設定」のON/OFF自体は「元に戻す」の対象に含まれない(チェックボックスを直接OFFに戻せば元の値に復元される)
29しおりツリー: ボタン配置・初期ウインドウサイズしおり編集画面を開き、1段目(レベル操作・追加3種・削除・レベル上限)・2段目(設定・戻る・元に戻す・一律設定2種・保存)の並び順と、初期状態でのウインドウ内へのボタン収まり具合を確認する指定の並び順になっている。初期ウインドウサイズ(1300×760)で、いずれの行のボタンも画面外にはみ出さずに収まっている
30ダイアログのEscキャンセル「子要素のレベル上限を設定」「PDFプロパティ」「アプリ設定」の各ダイアログを開き、何かフォーカスがある状態でEscキーを押すいずれのダイアログもキャンセル扱いで閉じる(変更が破棄される)
31表示言語の自動判定・切り替え初回起動(設定ファイルが存在しない状態)でアプリを起動し、UI言語を確認する。次に設定ダイアログで言語を切り替えて保存し、アプリを再起動する初回起動時、OSの表示言語が日本語ならUIが日本語、それ以外なら英語で表示される。設定ダイアログで切り替えて保存した言語は、次回起動時からUI全体(ウィンドウタイトル・ボタン・メッセージ・ダイアログ)に反映される(実行中の画面はその場では切り替わらない)
32設定ファイルの保存先アプリで何らかの設定を変更・保存した後、実行ファイルと同じフォルダを確認する。%AppData%/PdfBookmarkMerger/も確認する実行ファイルと同じフォルダにsettings.jsonが作成・更新されている。%AppData%/PdfBookmarkMerger/には設定ファイルが作成されず、logs/フォルダのみが存在する
